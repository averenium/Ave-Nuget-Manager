The closure page

Design for #109 — the second container. A closure too large to read in a popup, or one asked for on a row with nothing pending, opens on its own page: one editor tab beside the panel, a snapshot of what it was computed for, carrying the same single decision the popup carries. It is drawn here at the size it really is — an editor tab, with the whole closure in view — and it borrows the details panel's own pieces wherever there is one: the What changes band, the version-pair colours, the badges, the list selection. The tree is #137's component. Sample data uses Example.* names.

Decided in this round

  1. LA tree and a detail pane
  2. VThe pane opens on the closure's makeup
  3. AThe actions sit in a bar at the foot
  4. SA stale page shows a warning banner and disables the action
  5. DA dead end is always a popup
  6. TThe threshold is ten rows
  7. XThe page closes itself once it has acted
  8. NWFrom the popup file: "never offer to update dependents" — a ⋯ menu at the top right of the header while an apply is waiting; choosing it lets the waiting update go ahead (§11)
  9. FPThe other direction on the page: the range column is captioned Range and a forward row says required; the pane of a forward row states the requirement once and marks the versions that satisfy it (§12)
  10. ZHFrom the popup file: a dead end from two constraints, and a member moving against the root — both are popups; nothing of their own on the page
  11. CEIA central write (§13): the header names Directory.Packages.props and each project as a badge; every row has an In column saying which projects it was found in; a project that could not be judged is a dimmed row
  12. OYQFrom the popup file: the way out is always there — Update only this package beside a proposal, complete or partial, also when asked for on a row; Update anyway writes what was established, and where nothing was it is the way out
  13. RKGFrom the popup file: the range on the row, the root as a row, the guide line as #137 built it — used on every drawing here

Each is recorded under a Chosen heading below, with the other readings dropped. The popup is in dependent-cascade-popup.html.

Already decided — drawn as given, not reopened.

  • The page is one view opening beside the panel, not the panel moved; it reads the same bundle, stylesheet and theme tokens through a route flag, with a small host of its own. One page at a time; a second request reveals the open one.
  • It is a snapshot that carries its own actions: it names the package, the target version and the (project, framework) it was computed for, and goes stale explicitly when the panel has moved on. Its channel is three messages wide — the closure out, apply and block back.
  • No per-row checkboxes: the decision is the single one the popup takes; the extra room is for reading, not for turning one decision into twenty-three.
  • Could not establish is the same state as in the popup — unknown dependents dimmed, the reason in the range's place, both counts in the lead, Close when nothing is pending, Update anyway beside Cancel when an apply is (each with the way out the popup file's §5 adds), no tree and no Block this update when every dependent is unknown.
  • Elements neither file discusses keep the look they have; the tree is #137's as it landed — 14px a level with a guide line for three levels, then a 4px step and no line.

Not in the issue, and surfaced here rather than assumed: whether closing the tab cancels a waiting apply (drawn as cancelling, because the other reading leaves a write nobody can see); what the page does once it has acted (X); and a second request for a different package, where "reveal" and "stale" meet — whether it replaces the snapshot or leaves it stale is not settled; and Recompute on a stale page, which is a fourth message on a channel the issue draws three wide (§4).

1 · The page at editor-tab width

One editor tab beside the panel, drawn at 1,080px — about what a laptop editor gives it — with the whole closure in view: twenty-three rows are 524px of tree, so nothing is cut and nothing says and 17 more. The rows are live: click one and the pane changes, click ‹ This closure to come back. The hovered row on the first two drawings (ObjectPool) is drawn, not clicked.

Chosen: L — a tree and a detail pane — why

Named in review as the best of the three. The extra width has to be spent on something a popup cannot hold, and the issue says what: the extra room is for reading. This spends it on the reason. The row keeps the popup's shape — the forcing range on the row, R A in the popup file — so a closure reads the same on both surfaces, and the second pane carries what one line cannot: what the dependent declared before and declares now, and why this version of it. The plain row said "nothing" to the question and was dropped; the column layout printed a source on every row for a fact that is the same on most of them.

· What this leaves

Wording is new copy: the tab title, the lead sentences, the column captions, the foot line, This closure, the pane's labels and sentences, the banner, the chip, Recompute, Take all 23 anyway. Each is one sentence the implementation will read as a requirement.
The edge points the other way. In the details panel a row nested under X is something X needs; here it is something that needs X, and the range on it is what it declares for X. The captions say so in words; the popup file's tooltip is where the full sentence lives.
Nested rows are not dimmed here. DependencyTree takes a dimNested prop, off by default; the details panel turns it on and the cascade leaves it off, so every row is at full contrast and a dimmed row keeps meaning unknown.
The popup's answers are used here as drawn: the root as a row (K) — which on the page is the header, so the tree has no root row — and the guide line as #137 built it (G); the capacity table behind T is measured with that root row.
Not drawn: the reverse walk, the registration paging and the page's host — they have no surface of their own, and the issue covers them.
Colour: the page introduces none. The stale banner is the existing .sources-warn, the selection is the theme's own list pair, the green bar and the pair are the success colour the popup already uses, and the guide lines are the popup file's G.
