# Макети

HTML-етюди інтерфейсу. Кожен — самостійний файл, який відкривається у браузері й показує варіанти поруч, у кольорах теми VS Code. Макет створюється до коду, і саме з ним звіряється реалізація — елемент за елементом.

Макет потрібен не кожній задачі — лише тій, де змінюється те, що бачить користувач, і де є справжній вибір між варіантами. Виправлення, яке повертає задуманий вигляд, зміна формулювання або робота під капотом макета не потребує.

Правила:

- **Назва — описова**, kebab-case, без номера issue; звʼязок із задачею тримає таблиця нижче.
- **`<title>` англійською**, у формі `Що саме — design for #NN`. Вміст макета теж англійською, бо це UI-текст.
- **Нічого вигаданого.** Те, як воно виглядає сьогодні, береться з коду та з нитки issue, а не з пам’яті. Невідома деталь — це питання, а не припущення: вигадана дрібниця читається на етапі реалізації як вимога.
- **Усе вже прийняте — на макеті.** Рішення, ухвалені в issue, малюються всі. Якщо якесь із них тепер виглядає помилковим — це привід сказати про це, а не обійти його мовчки.
- **Вибір робить людина.** Перша версія макета містить варіанти й жодного `Chosen:`.
- **Обраний варіант позначено у файлі — після того, як його назвали.** Доки варіанти рівноправні, макет не готовий: наступний етап не має вгадувати, який із них узяли. Або лишається один варіант, або є явний заголовок `Chosen: …` з причиною.
- **Незачеплені елементи — як зараз.** Усе, що не є предметом обговорення, малюється рівно так, як уже виглядає в розширенні: без випадкових змін розміру, стилю чи розташування.
- **Обидві теми, коли йдеться про колір.** Світла й темна поруч; світла вимагає темнішого й спокійнішого відтінку, ніж темна.
