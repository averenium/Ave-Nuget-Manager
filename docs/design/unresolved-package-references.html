A package reference restore cannot resolve

Design for #138. A <PackageReference> that no source can supply is in the project file and nowhere in the panel: the list is what restore resolved, and a reference that failed is not in it. The issue's item 2 gives it a row and leaves how that row reads to a design pass — a state on the existing row, a section of its own, a count in the header — and items 3 and 5 leave two more visible decisions: what the details panel does for a reference that has no version to pick, and what the row says when restore has not run since the reference was added. Drawn at the panel's real sizes: the list at 300px, the details panel at 620px, every state at the height the rows really take. Sample data uses Example.* names; the restore messages are sample text in the shape NuGet writes them — the real text is the message in obj/project.nuget.cache.

Already decided in the issue — drawn as given, not reopened.

  • An unresolved reference gets a row carrying its declared version, an empty resolved version, and the reason from the restore log (item 2). The row is selectable, a different version can be picked for it, and it can be removed (item 3) — today the panel offers none of these, because there is no row.
  • The reason is the feed's own wording and the code beside it (NU1101, NU1102), read from obj/project.nuget.cache; a missing or unreadable file means nothing is known, never a row (items 1 and 6).
  • The declared version of a reference under central package management comes from Directory.Packages.props and is shown, never empty (item 4). Nothing in the panel says anything about central management today, so nothing is drawn for it beyond the version being there; the tooltip on the version is where the file would be named.

What the panel does today for such a reference: nothing. The drawing below is exactly that — the project declares six references and the list shows four.

Elements this file does not discuss keep the look they have: the rows, their marks (↑, the vulnerability triangle, the unmapped slash), the section headers, the details panel's header, selector, problems band and project rows are the real stylesheet's rules, copied. The attribute column of the details panel is left out of the crops.

3 · The details panel for such a row

Decided. Selecting the row lands somewhere that says why, offers a version where there is one, and offers Remove. Two facts shape it: when the id exists on the feed (NU1102) the panel has metadata; when no source has it (NU1101) there is no metadata to show, and the block that holds the Problems band is only rendered when there is. The message is the log's own, with the code in the band's severity slot and the framework it failed for after it, as an advisory carries its version. The picker opens on the declared version, which is not on the feed in the first case.
