## Mixed sources (some have `VulnerabilityInfo`, some do not)

The skip rule is **not** “run CLI if *any* source has a VDB.” `dotnet list --vulnerable` still walks **every enabled package source**. A working nuget.org next to Nexus still storms Nexus registration and waits on a result that will not come.

Run `--vulnerable` only when we will not send those doomed requests:

| Enabled package sources | Audit sources | CLI `--vulnerable` |
|---|---|---|
| Only nuget.org / `data.nuget.org` | anything | yes |
| Every enabled HTTP feed has working `VulnerabilityInfo/6.7.0` | anything | yes |
| At least one feed **without** VDB (Nexus, …) | **working** `VulnerabilityInfo` in `<auditSources>` | yes (VDB path; do not need Nexus for advisories) |
| At least one feed without VDB | missing, empty, or probe failed | **no** — skip; `VULNERABILITIES: []`; quiet Sources hint to add a correct `<auditSources>` |

nuget.org as a **package** source plus Nexus, without audit sources → skip (same as “not nuget.org-only”). Do not treat “nuget.org has VDB” as a green light to wait on the other feeds.

Quiet UX unchanged: no restore banner. HttpBackend VDB download still later.
