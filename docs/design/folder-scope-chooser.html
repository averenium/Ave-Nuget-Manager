Two axes, side by side. Left: the groupings — solutions, then everything. Right: the projects themselves. Neither is hidden behind the other, and the width goes to the only decision the panel needs.
The package list column is not drawn while there is no scope — no headings for lists that cannot exist, and nothing shimmering to promise data that is not coming. It returns unchanged the moment a scope is set.
Pointing at a solution shows what it holds. Here Example.Tools.slnx is under the pointer and its three projects stay lit while the rest dim. Which projects a solution covers is exactly what a reader is trying to work out, and side-by-side columns are what make it showable at all.
Solutions first, the one at the folder root ahead of the rest, then by depth, then by modification time.
Each option says what it covers — the project count for a solution, “ignores solution boundaries” for the folder, target frameworks for a project. That is what turns an ambiguous choice into an obvious one.

Three ways back, and none of them is a guess. The button says what returning means by naming the scope it returns to — Keep Example.Shop.sln — rather than saying Cancel and leaving the reader to work out what that undoes. Esc does the same, and the corner control is a toggle: the press that opened this closes it.
The package list stays on screen, dimmed. That is the difference from the first-open state, and it is deliberate: seeing the packages of the current scope behind the chooser is what makes it obvious that nothing has been given up yet. An empty body here would read as though the scope had already been dropped.
The current scope is marked rather than hidden — it stays in the list, checked, so the reader can see where they are in the set of choices. Choosing it again simply closes the chooser.
Nothing is committed until a row is clicked. Opening the chooser changes nothing; the reload happens on the choice, which is also when the dimmed list is replaced.
Same layout as the first open, so the second encounter needs no relearning: what changed is the header line and the check mark, not the shape.

The same two columns hold when there is nothing to group by: the left one carries a single answer rather than a list, and the right one keeps its place, so the layout does not rearrange itself between folders. Nothing dims here — there is no solution to point at.

Not changed by this design: the tab bar, the toolbar and its controls, the details area once a scope exists, and the behaviour of the corner control after a choice — it still shows the current scope and still reopens the picker. The package list column is unchanged too; it is simply absent while there is nothing it could list.
