## Plan

Not “export the Log tab”. A **trace session**: off by default, Start records verbose diagnostics, Stop sanitizes and packs a zip for a GitHub issue. The Log tab stays the normal CLI view, plus a **Clear log** button.

### Cycle

1. **Start trace** (Log toolbar and/or Command Palette). Short **confirm**: recording will include CLI, sanitised `nuget.config`, and sanitised project files from the current scope; do not commit the zip. Badge that recording is on. Write to a session folder under `globalStorage` (`trace-<iso>/`), not an unbounded in-memory buffer.
2. User reproduces the bug (restore, All, install, …).
3. **Stop & pack**. Sanitize every file → zip → Save dialog / Reveal in OS. Toast: attach the zip to the issue. Do **not** open GitHub with credentials or POST the archive.

Start while a session is live: no-op, or prompt to Stop first.

**Hide panel** (`retainContextWhenHidden`): do not stop the trace.

**Extension Host reload:** the raw session folder may survive in `globalStorage`. On next `activate()`, if a session dir exists without a finished zip: offer **Stop & pack** or **Discard**. Do not keep recording forever with no UI.

### What trace records (only while on)

Today the logger is almost only `CliRunner` (`dotnet …` + absolute paths). While tracing, also:

- webview → host: message `type`, payload truncated (no unsanitized csproj bodies in the JSONL);
- broker steps: init scope, snapshot, add/remove per project, batch item, enrich retry, vuln scan;
- CLI `cwd`, duration, exit, full stdout/stderr;
- session header: extension version, VS Code/Cursor, OS, `dotnet --version`.

**Include in the zip** (after sanitizers): CLI/trace logs, `nuget.config` chain, **scope project files**, nearest **Directory.Packages.props**, **Directory.Build.props** (if present), **global.json** (SDK pin), **packages.config** on legacy projects, optional sanitised **.sln**, **blockedPackages**. Never include: raw secrets, full `.vscode/settings.json`, source `.cs` / `appsettings`, `bin`/`obj`, User secrets store.

### Sanitize before zip (logs, env, XML)

Apply **longest path first** (workspace roots, then home). Otherwise `C:\Users\<name>\repo` rewrites badly.

| Replace | With |
|---|---|
| `os.homedir()`, `C:\Users\<name>`, `/Users/<name>` | `~` |
| workspace folder roots | `<workspace>` |
| hostname, emails | `<host>` / `<email>` |
| `://user:pass@`, `password=`, `ClearTextPassword`, `apikey=`, connection strings | `<redacted>` |

Keep: package ids, versions, NU codes, `.sln` / `.csproj` **file names**, exit, duration. `~\.nuget\packages\…` after home rewrite is fine.

Do not hand out a zip of the unsanitized temp folder.

### nuget.config

Copy each file from `NuGetConfigChainResolver` (nearest → global) as `nuget-config/00-<role>.xml`, … after stripping identity:

- Drop or empty `<packageSourceCredentials>`, `<apikeys>`, Password / Username / PAT / apiKey.
- Local folder sources: same path rewrite as logs.
- Private feed URLs: keep shape (https, v2/v3, azure vs nuget.org); org/project/user → `<org>`, `<project>`. Leave nuget.org as-is.
- Keep source keys, enabled/disabled, mapping, `<clear/>`.

Unreadable file → stub with sanitized path + error, not raw XML.

### Project files

Needed for duplicate PackageReference, SDK vs legacy, TFM, CPM, SDK pin. At Stop, copy **current scope** only:

- solution: every `.csproj` / `.fsproj` from `scope.projects` + nearest `Directory.Packages.props` / `Directory.Build.props` per walk (one copy per unique path, not once per project);
- `global.json` from the workspace (or nearest above the solution);
- `packages.config` next to a legacy csproj, if present;
- optional: the `.sln` / `.slnx` (project list, little PII);
- project scope: that one project + its props.

Layout: `projects/<fileName>.csproj` (if two share a name, prefix with a sanitized relative path). Same XML sanitizer as configs. Strip `HintPath` user folders.

Cap: if more than e.g. 40 projects, include those touched by the session (install/batch paths) plus a `projects-omitted.txt` count.

### blockedPackages

Export **only** `averenium.nugetManager.blockedPackages` (package ids), not the rest of settings:

```
blocked-packages.json
```

Empty list → still include `{ "blockedPackages": [] }`.

### Archive layout

```
nuget-manager-trace.zip
  README.txt
  env.txt
  trace.jsonl
  cli.log
  blocked-packages.json
  nuget-config/00-nearest.xml …
  projects/Foo.csproj
  projects/Directory.Packages.props
  projects/global.json
```

Cap the session (e.g. 10–20 MB or 30 min): drop oldest **log** lines, set `truncated` in README. Project/config copies are a snapshot at Stop, not tailed.

Host builds the zip. Prefer OS `tar` (Windows 10+, macOS, Linux) or a small zip lib in the host — not PowerShell-only. Webview only sends `START_TRACE` / `STOP_TRACE`.

### Log tab and commands

Keep the current CLI list. Toolbar:

- **● Trace** / **■ Stop & save zip**
- **Clear log** — wipe in-memory `Logger`, Output Channel, and the webview list. Does **not** stop an active trace or delete the session folder. v1: clear immediately (no undo).

Same three actions as Command Palette commands so they work if the Log tab cannot open.

Recording badge while trace is on. Verbose events stay in the session files so the webview does not render the full trace.

### Out of scope

- Auto-upload to GitHub
- Telemetry
- Always-on file log in the repo
- Raw (unsanitized) configs or project files
- Entire `.vscode/settings.json`
- Zip preview before save
- `bin` / `obj` / `appsettings` / `.cs`
