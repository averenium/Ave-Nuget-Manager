5 · Proceeding as asked

Raised in review. The confirmation offered Cancel or Take all, so once the popup interrupted an apply there was no way left to do the one thing that was asked — update this package alone. Before this feature that is what would have happened (restore warns, nothing blocks); the popup had taken it away. This is not a way to leave one dependent out: a cascade's members are still causally linked, and there are still no checkboxes. It is a way to decline the proposal as a whole and write only what was asked. That reopens "one decisive action" in the first design comment and item 6's "the single decision the popup takes" — the proposal is still one decision, taken or declined whole, and declining now has a button. The way out is offered in every state — whether a write is waiting or the check was asked for on a row (Q, below). Every popup above that interrupts an apply is drawn with it.

· What this leaves

Nested rows are not dimmed here. The details panel dims every nested dependency; DependencyTree takes a dimNested prop, off by default, which the details panel turns on and the cascade leaves off. Every row here is a package that will move, so every row is drawn at full contrast and a dimmed row keeps meaning unknown.
An edge that points the other way. In the details panel a row nested under X is something X needs, and the range on it is what X declares for it. Here a row nested under X is something that needs X, and the range on it is what it declares for X. The slot is the same and the arrow is reversed; the tooltip on the range should say so (Example.Messaging.Bus 8.1.1 declares Example.Messaging.Transport [7.2.0, )), and the lead sentence already names the first edge.
A dependent that is itself transitive. Only direct references can be proposed, and a transitive can only move through its parent. The issue decides that; this file does not draw the row that has to say so — it has no version pair to show.
Reason wording is new copy, and so is the page tab's title and every lead sentence here. Each is one sentence the implementation will read as a requirement.
How many rows each choice holds — the figures that decide the threshold — are in the page file, under the threshold (T).
The way out reopens earlier lines. The first design comment's "one decisive action", item 6's "the single decision the popup takes", and the body's "asked for on a row, the only action is Close" for an unknown set: the proposal is still taken or declined whole, with no checkboxes, and declining now has a button in every state. Worth saying in the issue, so that items 5 and 6 are built from this and not from those lines.
Take all N counts the dependents — the "other packages" of the lead — and the page's foot counts the changes, the bump included (Take all 23 beside 24 changes), which is how the build counts. Take both is the one-dependent case. The three-hop popup said Take all 3 for two dependents until this pass.
"Never offer" is a second setting. The feature has one today, experimentalHttpCatalog, which gates whether the check can run at all; this one gates whether it interrupts an apply, and the right-click question ignores it. Its name and its scope — the user's or the workspace's — are the implementation's; the mockups say only "Settings".
A popup narrower than 456px cannot hold the four-button row past the threshold. .popup__actions has no wrap today, so the row has to gain one — a modifier on the row, not a change to the popups that already fit.
Colour: nothing new — the guide is #137's --color-tree-guide, and both themes are drawn. The dimming of an unknown row is the existing popup__item--incompatible opacity, the version pair is popup__ver--up/--down's green and gold, and the buttons are the real .btn.
